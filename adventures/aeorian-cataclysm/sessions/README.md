# Sessions — วิธีใช้โฟลเดอร์นี้

โฟลเดอร์นี้เก็บ **รายละเอียดระดับ session จริง** แยกจากไฟล์ ACT0X.md ที่เป็น outline หลักของทั้งแคมเปญ — ใช้หลักการ **just-in-time**: ไม่พยายามลง detail ทั้งแคมเปญล่วงหน้าทีเดียว (เสียเวลาถ้าโต๊ะเล่นเบี่ยงจากแผน) แต่เตรียมทีละ session ก่อนเล่นจริง แล้วบันทึกสิ่งที่เกิดขึ้นจริงหลังเล่นจบ

1 ไฟล์ = 1 session จริง ตั้งชื่อ `session-01.md`, `session-02.md`, ... เรียงตามลำดับที่เล่นจริง (ไม่ใช่ตามลำดับ Act ในโครงเรื่อง เพราะบาง session อาจเล่นได้ไม่ถึง 1 ช่วงของ Act หรือบางทีข้ามหลายช่วงในคืนเดียว)

## โครงไฟล์ต่อ session

```markdown
# Session NN — <ชื่อสั้นๆ ของคืนนั้น>
**วันที่เล่นจริง**: <วันที่>
**อ้างอิง Act**: [ACT0X](../ACT0X-xxx.md) ช่วง "<ชื่อหัวข้อย่อยใน Act>"
**Level เข้า/ออก**: <level ตอนเริ่ม> → <level ตอนจบ>

## แผนก่อนเล่น (Prep)
ดึงเนื้อหาจากหัวข้อย่อยที่เกี่ยวข้องใน ACT0X.md มาขยายเป็น detail ระดับเล่นจริง — boxed text/บทบรรยาย, stat block ที่จะใช้ (หรืออ้างอิงชื่อมอนสเตอร์จาก 5etools), DC เฉพาะจุด, บทพูด NPC สำคัญ ฯลฯ

## สิ่งที่เกิดขึ้นจริง (Actual Play Log)
เขียนหลังเล่นจบ — สรุปว่าเกิดอะไรขึ้นจริง ตรงกับแผนแค่ไหน มีอะไรเบี่ยงจากแผนบ้าง (ตัวละครเลือกทางอื่น, บอสตายไวกว่าคิด, มี NPC ตายที่ไม่ควรตาย ฯลฯ)

## Continuity Notes
สิ่งที่ session ถัดไปต้องจำ — ของที่ได้มา, สัญญาที่ให้ไว้กับ NPC, ความสัมพันธ์ที่เปลี่ยนไป, ปมที่เปิดใหม่ระหว่างเล่น ฯลฯ (สิ่งเหล่านี้อาจทำให้ ACT0X.md ต้องแก้ตามถ้ากระทบเนื้อเรื่องหลัก)
```

## เมื่อของจริงเบี่ยงจากแผน (ACT0X.md)

ถ้าสิ่งที่เกิดขึ้นจริงในเล่นเปลี่ยนเนื้อเรื่องหลักอย่างมีนัยสำคัญ (เช่น NPC ที่ควรรอดถึง Act หลังดันตายไปแล้ว, ตัวละครข้าม encounter สำคัญไป) ให้อัปเดตไฟล์ ACT0X.md ที่เกี่ยวข้องด้วย ไม่ใช่ปล่อยให้ outline กับของจริงเพี้ยนออกจากกันเรื่อยๆ — session log คือ "สิ่งที่เกิดขึ้นจริง" ส่วน ACT0X.md คือ "แผนที่ปรับให้ตรงกับของจริงล่าสุดเสมอ"
